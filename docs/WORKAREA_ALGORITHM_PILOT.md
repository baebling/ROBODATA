# Fireproof Workarea Algorithm Pilot

Executed on 2026-10-03 after the researcher requested testing the local
`fireproof_workarea` package. Its original code, checkpoint, input recordings
and acceptance thresholds were preserved. No SDK, drivers or dependencies
were installed. This is a development diagnostic, not a new untouched benchmark.

## What Actually Ran

| Trial | Input | Result | Claim boundary |
|---|---|---|---|
| Original `ArraySurfaceRecognizer` and `real_best.pt` | Initial calibrated RGB plus ideal simulator depth in 16 helmet conditions | 0/16 accepted initial five-face recognitions | RGB-D initialization module, not FFS, SVO replay or tool pose |

The tracker was initialized directly from the first RGB/depth pair even though
the recognizer failed. Its 46 outputs must not be counted as full-pipeline
successes. No `T_surface_tool`, nozzle pose, tool trajectory, IK or physical
robot execution was generated by these tests.

## Inputs And Isolation

The existing `outputs/helmet_sensors_20261003_02` contains 16 eight-frame
sequences: four nominal sensor viewpoints and four distance/pitch conditions.
All 128 RGB frames were used for the tracker trial; each first reference frame
was excluded from scoring, leaving 112 frames. The recognition trial used just
the 16 initial frames. Previous raw scenes, renders and results were unchanged.

Depth is ideal renderer depth, not actual ZED stereo or Helios ToF measurements.
Its declared ray-distance/axial convention is respected. Independent rendered
sample checks validate the raw initial depth with 5 mm absolute tolerance and
zero relative tolerance before conversion. There is no scale fitting. Smartphone
conditions use a hypothetical external RGB-D initialization; no phone depth
sensor or metric RGB-only reconstruction is claimed.

Inference receives RGB, matching intrinsics and the initial depth only. Later
depth, simulator poses, GT masks/keypoints and ZED VIO are excluded. Simulator
camera transforms enter scoring only after tracking. Failed outputs remain
null; no stale pose, interpolation or held reference is substituted.

The original tracker is copied byte-for-byte into its output directory. The
recognition package is copied into a separate output sandbox before importing
its file-oriented modules, whose normal import/runtime side effects would
otherwise create files inside the source package. It uses the original trained
checkpoint, not the previous ROBODATA YOLO checkpoint. No five-face support
threshold or candidate mask gate was relaxed.

## RGB Tracking Results

Final scored run: `outputs/workarea_tracker_20261003_02/comparison.json`.

- Initialization: 16/16, but reference captures are not successful estimates.
- Returned/accepted poses: 46/112 (41.1%); 66 rejected with `pose_review`.
- Conditional mean camera-position error: 0.121737 m (12.17 cm).
- Conditional maximum camera-position error: 0.351931 m (35.19 cm).
- Conditional mean orientation error: 6.426947 degrees.

Position compares camera centers expressed in the initial camera frame, not
the translation of the map origin in the moving camera. The original tracker
outputs `T_current_camera_initial_camera`; both predicted and reference
transforms are inverted for camera-center position scoring. Rotation is the
relative rotation angle. All-error summaries are conditional on returned
poses; rejected frames have no measured pose error, not zero error.

| Nominal profile | Far/aimed | Near/aimed | Normal/aimed | Normal/level | Total |
|---|---:|---:|---:|---:|---:|
| Helios | 7/7 | 0/7 | 3/7 | 0/7 | 10/28 |
| Galaxy main | 6/7 | 0/7 | 1/7 | 0/7 | 7/28 |
| Galaxy ultrawide | 7/7 | 0/7 | 6/7 | 1/7 | 14/28 |
| ZED | 7/7 | 0/7 | 7/7 | 1/7 | 15/28 |

These are nominal synthetic viewpoints, not rankings of real sensor quality.
All near conditions fail after initialization. More returned poses need not
mean higher accuracy: ZED/far and ultrawide/far average about 21 cm position
error while returning all seven estimates. Static background scarcity,
occluding/moving tool features and viewpoint are hypotheses for follow-up
ablations, not isolated causes established by this run.

Run01 is retained as a development run. Review corrected position scoring from
map-origin translation to camera-center position, and added strict calibration
and independent depth checks. Run02 reran all conditions; acceptance counts
were unchanged. Its exact executed runner is preserved at
`upstream/workarea_pilot_executed.py` with a hash matching `runner_sha256`.
The checked-in runner subsequently received formatting-only line wrapping.

The contact sheet shows raw RGB and tracking status/error, not a predicted
semantic surface overlay. This camera-motion result is not directly comparable
with the prior YOLO semantic surface localization count of 9/128.

## Original Workarea Recognition Results

`outputs/workarea_recognition_20261003_01/summary.json` records actual execution
of the original array recognizer and checkpoint on all 16 initial frames.

- Seven attempts reached the S1-S5 support gate and were rejected for missing
  observed faces. The exact insufficient face IDs are retained per case.
- Nine attempts stopped for insufficient work-area point cloud, with zero
  selected work points. This is not a successful surface segmentation result.
- Accepted initial reference models: 0/16. There is no accepted surface pose
  error or downstream trajectory metric to report.

The source pipeline combines learned beam masks, an exposed-red work-area
candidate and topology-based five-face completion/validation. The helmet
simulation looks primarily at the web and uses an illustrative gray beam and
large white hopper, unlike the source appearance assumptions. The logs show
the gate failures; they do not alone prove which appearance or geometric
factor caused them. A single observed web plane must not silently be treated
as five observed faces. Relaxing the gate would require a separately specified
web-only algorithm with its own observability and persistent identity tests.

Original module provenance may describe its array depth as FFS depth. In this
trial it was explicitly substituted with ideal renderer depth; FFS inference
and the live pipeline did not run. Our trial summary records that distinction.

## SVO And Coordinate Audit

`outputs/fireproof_svo_20261003_01/summary.json` and its runtime logs document
the environment check. The SVO was not opened: `replay_started=false`,
`fully_replayed=false`, and `counts_available=false`. Six candidate Python
runtimes lacked usable `pyzed.sl`; inspected Linux SDK paths were absent.
Some protected Windows locations could not be enumerated. No actual SVO
recognition success/failure rate is available from this attempt.

The isolated pure-function audit at
`outputs/workarea_tracker_20261003_01/coordinate_audit.json` tests original
`src/zed_face_pipeline.py::choose_web_local_frame` on a planar grid at z=2 m.
A normal toward the camera, [0,0,-1], produces determinant -1; the opposite
normal produces determinant +1. A one-axis PCA sign flip can create a
reflection, which cannot be used as a valid SE(3) rotation. This is a utility
counterexample, not evidence that every original classification result has
that defect. These axes were not used by the tracker and are not exported as
ROBODATA canonical actions. The external source was not changed.

## Interpretation And Next Boundaries

The original algorithm is executable in isolated components and is useful as
a comparison baseline. The present tests do not establish that it maintains
an accurate helmet-mounted work-surface frame or produces robot-ready tool
labels. Five-face initialization currently blocks the unchanged chain.

Next engineering experiments should separate web-only recognition from full
five-face reconstruction, verify a stable right-handed semantic web frame,
and compare static-background feature selection against unrestricted features
without changing reserved RGB inputs or hiding invalid frames. Actual SVO
replay needs a compatible ZED SDK runtime; real metric validation also needs
measured calibration and independent GT. Any resulting tool action still
requires an independently estimated tool/nozzle pose and the frame composition
`T_surface_tool = inverse(T_camera_surface) @ T_camera_tool`.

Fresh verification: 248 repository tests pass, including 14 focused adapter
tests; 53 files pass formatting, lint passes and mypy passes 31 source files.
Independent read-only review confirmed the camera-center scoring and the
calibration/depth guards, including actual initial depth samples. It did not
independently validate the full recognition/tracking performance results.
